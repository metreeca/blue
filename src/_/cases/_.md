# Blue Limitations

## Shape cycles infer by declaration order

A cycle closed by an `extends` edge infers only when the extending shape is declared before the parent it extends;
otherwise both ends fail with `TS7023: 'Dataset' implicitly has return type 'any' because it does not have a return
type annotation and is referenced directly or indirectly in one of its return expressions`. Cycles closed purely by
references infer at any order and any length.

Ordering carries most of the vocabulary: `OrganizationalUnit` precedes `Organization`, `ImageObject` precedes `Thing`.
It stops short where the parent also references the extending shape back, closing a second cycle through the two
reference edges that no declaration order untangles: `Organization.hasUnit` is cut with an explicitly annotated
`reference((): ResourceShape => …)` thunk for that reason. The same cut applies where a cycle closes through a shape
declared in another module and there is no ordering knob at all, as `Resource.dataset` and `Resource.university` do. The
annotation carries no type cost: `reference()` types its target as `Lazy<ResourceShape>` in any case.

Cut the reference edge, never the `extends` edge: annotating a parent as `ResourceShape` compiles silently and empties
every inherited entry.

## Captive references project to a bare IRI

A captive reference accepts either an IRI or the target resource inline: `validateReferenceElement`
(`Packages/Blue/src/resource.core.ts:855`) validates an object value against the target shape whenever `captive` is set.
`State<>` admits only the IRI, since it resolves through `Instance<Schema<S>>` and a reference carries the `app` model
whatever its target, so the inline form has no type to name. Writing a captive target inline therefore takes a cast.

`Event.image` is where this bites: the event converter (`src/events/tasks/convert.ts:103`) can populate the image IRI
but not the `caption`, `author` and `copyrightNotice` that come with it, so the extracted image credits are dropped.

## Reference refinement stops at embedding, arity and cycles

An inherited reference re-points at a target extending the inherited one:
`resource({ extends: Parent }, { ref: required(reference(Narrower)) })` merges to `Narrower` where `Parent.ref` targets
`Wider`, and the inherited definition reaches the narrower target through its own `extends` chain. An unrelated target
compiles and fails only at run time, as
`incompatible resource shape override <[{"link": ["{shape} incompatible <shape> override"]}]>`.

Swapping an inherited reference for an embedded resource fails as `{kind} mismatched kinds <resource> vs <reference>`,
so embedding overrides stay out of reach.

Cardinality is refinable within the same arity, but not across it: the projected value type follows from arity, so
raising a minimum count ports unchanged, while capping an inherited set at a single value does not. Only the projected
type rejects the narrowing; the override check itself accepts it.

Cycles close the remaining ground, since shapes are declared as functions rebuilt on every call and the override
resolves both ends eagerly. Re-pointing a property at the very shape that declares it fails as
`circular extends chain <[{"Organization": ["circular dependency"]}]>`. Refining both ends of a pair that point at
each other exhausts the stack with `RangeError: Maximum call stack size exceeded`, naming no property, so a mutually
referencing pair admits one refined direction only.

A thunk on the path defeats the check outright. The lineage is matched by structure, and `reference(() => …)` builds a
fresh closure on every call, so two builds of a shape carrying a thunk never compare equal: any target reached through
one is rejected as `{shape} incompatible <shape> override`, however the hierarchy actually reads.

## Standing against the sketch

Each limitation as it reads against the `src/_` sketch, measured rather than reasoned.

| Limitation                                      | Standing | Notes                                                            |
|-------------------------------------------------|----------|------------------------------------------------------------------|
| Cycles infer by declaration order               | Closed   | Either end may be declared first, whatever closes the cycle      |
| Captive references project to a bare IRI        | Closed   | A submitted resource is described by `Draft`, not by `State`     |
| An unrelated reference target compiles          | Covered  | Caught by `narrowsReference`; statically closeable too           |
| Embedding overrides stay out of reach           | By design| Embedding an inherited reference swaps an IRI for a record       |
| Cardinality is not refinable across arity       | By design| Capping an inherited set swaps an array for a bare value         |
| Re-pointing at the declaring shape fails        | Closed   | A property may name the shape that declares it                   |
| A thunk on the path defeats the override check  | Closed   | Ranges are matched by shape kind, so closures no longer matter   |

Two of these are not limitations at all. An extending shape may tighten what it inherits, never restate it in a form
its extended shape cannot stand in for: code holding the extended state has to accept every extending instance. Capping
an inherited set at a single value hands a bare value where an array was expected, and embedding an inherited reference
hands a record where an IRI was expected, so both are refused whatever else they narrow.

Declaration order was never inherent to shape cycles: it came of checking overrides in the `resource` signature, which
resolves an extended shape while the extending one is still being inferred. Checking them where the state resolves
keeps the check and drops the constraint.

A re-pointed reference target is matched by shape kind alone, so any reference narrows any other whatever it targets.
`narrowsReference` (`Packages/Blue/src/reference.core.ts:73`) closes this where the shape is built, walking the lineage
of the refined target and demanding the inherited one among its ancestors, directly or transitively, through any parent.
It rejects a redefined `foreign` or `captive` alongside. The same predicate is expressible over the declared parents,
so the check could also stand where the state resolves:

```typescript
type Ancestry<S extends Lazy<ResourceShape>>=
	Eager<S> extends { readonly extends: infer P extends Parents } ? P[number] | Ancestries<P> : never

type Extends<C extends Lazy<ResourceShape>, P extends Lazy<ResourceShape>>=
	[P] extends [C] ? true : [P] extends [Ancestry<C>] ? true : false
```

Either way shapes are matched by structure, so two shapes carrying identical members are indistinguishable and a target
reached through one is accepted for the other.

A captive target is supplied inline on submission, never on retrieval, so the inline form belongs to a value type of
its own rather than to the retrieved one: unioning it into `State` would leave every reader narrowing an alternative a
retrieved resource never carries.

A shape accordingly describes two value types. `State` states what a retrieved resource carries, a reference always as
an IRI. `Draft` states what a submitted one carries, dropping the members the resources they point at own, leaving
optional the identifier and the members the system populates, and admitting a captive target inline alongside its IRI
at whatever cardinality the member states. Captive drafts nest, so a captor and the resources it holds captive travel
together.

| Member                        | `State`     | `Draft`                  |
|-------------------------------|-------------|--------------------------|
| plain property                | as declared | as declared              |
| plain reference               | IRI         | IRI                      |
| `captive` reference           | IRI         | IRI or the target draft  |
| `computed`                    | required    | optional                 |
| identifier                    | required    | optional                 |
| `foreign`                     | present     | absent                   |

This cost the reference shape a target to name the inline form, and the property factories a `const` constraints
parameter so that `captive`, `computed` and `foreign` survive as literals rather than widening to `boolean`. A cycle
closed through a captive edge no longer terminates, since the inline form has to name the target state, but a captive
resource cannot outlive the one holding it and so cannot legitimately close one.
